# Defender Tray

אייקון במגש המערכת של Windows שמראה במבט אחד אם **ההגנה בזמן אמת** של Microsoft Defender פעילה,
ומאפשר להדליק או לכבות אותה מתפריט — בלי לפתוח את "אבטחת Windows".

| האייקון | המשמעות |
|---------|----------|
| מגן **ירוק** | ההגנה בזמן אמת פעילה |
| מגן **אדום** | ההגנה בזמן אמת כבויה |
| מגן **אפור** | לא ניתן לקרוא את מצב Defender |

> ## ⚠️ אזהרת אבטחה
> כיבוי ההגנה בזמן אמת **מקטין את אבטחת המחשב** וחושף אותו לתוכנות זדוניות.
> כבה אותה רק לזמן קצר, למטרה מוגדרת, והחזר אותה מיד לאחר מכן.
> השימוש בכלי הוא באחריות המשתמש בלבד. ראה את סעיף האחריות שב-[LICENSE](LICENSE).

## התפריט

לחיצה על האייקון (שמאלית או ימנית) פותחת את התפריט:

```
┌──────────────────────────────────────────────┐
│  הגנה בזמן אמת: פעילה                        │   ← שורת מצב, מעומעמת (לתצוגה בלבד)
│  הגנה מפני טיפול שלא כדין חוסמת את המתג      │   ← מופיעה רק כשההגנה מפני טיפול פעילה
│  כבה הגנה בזמן אמת                           │   ← המתג עצמו
│  ──────────────────────────────────────────  │
│  פתח את הגדרות ההגנה                         │   ← פותח את "אבטחת Windows"
│  הפעלה עם ההתחברות                        ✓  │   ← מתג משימה מתוזמנת
│  ──────────────────────────────────────────  │
│  יציאה                                       │
└──────────────────────────────────────────────┘
```

שורת המתג מתחלפת לפי המצב: `כבה הגנה בזמן אמת` כשהיא פעילה, `הפעל הגנה בזמן אמת` כשהיא כבויה.
כשאין גישה ל-Defender היא מוצגת כ-`אין גישה ל-Defender` ומנוטרלת.

## התקנה והרצה

**דרישות:** Windows 10 או 11, עם Windows PowerShell 5.1 (מותקן כברירת מחדל).

1. הורד את התיקייה (או `git clone`) למיקום קבוע — למשל `C:\Tools\defender-tray`.
2. הפעל בלחיצה כפולה על **`defender-tray.cmd`**.

הקובץ `defender-tray.cmd` מריץ את הסקריפט בלי חלון קונסולה:

```bat
start "" powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File "%~dp0defender-tray.ps1"
```

אפשר גם להריץ ישירות:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Tools\defender-tray\defender-tray.ps1"
```

> **חשוב:** אל תעביר את הקובץ אחרי שהפעלת "הפעלה עם ההתחברות" — המשימה המתוזמנת שומרת את
> הנתיב המלא שממנו הורצה. אם הזזת את התיקייה, כבה והדלק את האפשרות מחדש.

### בדיקת מצב מהטרמינל

הדגל `-CheckOnly` מדפיס את המצב ויוצא — **בלי הרמת הרשאות ובלי לתפוס את נעילת המופע היחיד**,
כך שאפשר להריץ אותו גם כשהכלי כבר רץ במגש:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "defender-tray.ps1" -CheckOnly
```

פלט לדוגמה:

```
RealTime=False  Tampered=False  Tooltip="הגנה בזמן אמת: כבויה"  Toggle="הפעל הגנה בזמן אמת"  Startup=True
```

## הרשאות מנהל

**קריאת** המצב עובדת בלי הרשאות מיוחדות. **שינוי** המצב מחייב הרשאות מנהל, ולכן הכלי מרים
את עצמו אוטומטית דרך UAC בהפעלה רגילה — תופיע בקשת אישור אחת, פעם אחת לכל הפעלה.

אם תבטל את בקשת ה-UAC, הכלי פשוט לא יעלה.

הפעלה עם `-CheckOnly` אינה מרימה הרשאות ואינה מציגה UAC.

## ⚠️ הגנה מפני טיפול שלא כדין (Tamper Protection)

**זו הסיבה הנפוצה ביותר לכך שהמתג "לא עובד".**

"הגנה מפני טיפול שלא כדין" היא מנגנון של Windows שחוסם שינוי הגדרות Defender בידי תוכנה
כלשהי — כולל סקריפטים. כשהיא פעילה, הפקודה `Set-MpPreference` שהכלי משתמש בה **נחסמת בשני
הכיוונים — גם בכיבוי וגם בהדלקה**. אין דרך לעקוף אותה מתוך סקריפט, וזו התנהגות מכוונת של
Windows, לא תקלה בכלי.

כשהכלי מזהה שהיא פעילה הוא מציג בתפריט את השורה
`הגנה מפני טיפול שלא כדין חוסמת את המתג`, וכשלוחצים על המתג הוא מסביר זאת בחלון הודעה.

### איך לכבות אותה

היא נשלטת רק ידנית, מתוך ממשק Windows:

> **אבטחת Windows** ← **הגנה מפני וירוסים ואיומים** ← **ניהול הגדרות**
> ← **הגנה מפני טיפול שלא כדין** → כבה

(אפשר להגיע לשם ישירות דרך `פתח את הגדרות ההגנה` שבתפריט הכלי.)

לאחר הכיבוי המתג יעבוד. שים לב שכיבוי "הגנה מפני טיפול שלא כדין" הוא בעצמו החלשה של
האבטחה — שקול להחזיר אותה כשסיימת.

> במחשב מנוהל (ארגון / דומיין) ייתכן שהאפשרות אפורה ונשלטת במדיניות — במקרה כזה
> אי אפשר לכבות אותה מקומית, והמתג לא יעבוד.

## ההשהיה של עד דקה

Defender **לא מחיל את השינוי מיד**. לאחר לחיצה על המתג המצב בפועל מתעדכן תוך **עד דקה**.

לכן הכלי לא בודק את התוצאה מיד אחרי הפקודה — הוא מציג בלון "הבקשה נשלחה", ואז עוקב אחרי
המצב האמיתי כל 3 שניות עד שהוא באמת משתנה, ורק אז מציג "ההגנה בזמן אמת הופעלה/כובתה".
אם לא חל שינוי בתוך שלוש דקות, מוצגת הודעה שייתכן שמדיניות ארגונית או תוכנת אבטחה אחרת
חוסמת את השינוי.

**זה תקין ומכוון.** בזמן ההמתנה האייקון עדיין מציג את המצב הישן — כי זה המצב האמיתי.

## הפעלה עם ההתחברות

הפריט `הפעלה עם ההתחברות` רושם משימה מתוזמנת בשם `DefenderTray`:

* טריגר: התחברות משתמש
* רמת הרצה: **Highest** — כך הכלי עולה מורם **בלי בקשת UAC** בכל התחברות
* ללא הגבלת זמן ריצה, ורץ גם על סוללה

לחיצה נוספת על הפריט מבטלת את הרישום ומוחקת את המשימה. הסימון `✓` בתפריט מציג את המצב הנוכחי.

הסרה ידנית:

```powershell
Unregister-ScheduledTask -TaskName 'DefenderTray' -Confirm:$false
```

## צריכת משאבים

| מדד | ערך |
|-----|-----|
| זיכרון | כ-**15MB** |
| מעבד | כ-**0.3% מליבה אחת** |

הכלי בודק את המצב כל 3 שניות, אבל כמעט בלי עלות: הבדיקה התכופה משתמשת ב-`root/SecurityCenter2`
שהוא זול משמעותית, ורק כשהערך שם זז נקראת השאילתה המלאה והיקרה של Defender. בנוסף היא נקראת
אחת לדקה בכל מקרה, כדי לזהות שינוי במצב "הגנה מפני טיפול שלא כדין" — הוא אינו משתקף בבדיקה הזולה.

התפריט עצמו אינו מריץ שום שאילתה בפתיחה, ולכן הוא נפתח מיד; הוא מציג את המצב שהטיימר כבר החזיק.
בנוסף, אחת לדקה הכלי מבקש מהמערכת לגזום את ה-working set שלו, כדי ש-PowerShell לא יחזיק
זיכרון גדול בהרבה ממה שכלי מגש צריך.

## פתרון תקלות

| תופעה | סיבה אפשרית |
|--------|--------------|
| המתג לא משנה כלום | "הגנה מפני טיפול שלא כדין" פעילה — ראה למעלה |
| המצב לא השתנה מיד | תקין: Defender מחיל את השינוי תוך עד דקה |
| אייקון אפור | לא ניתן לקרוא את מצב Defender (השירות כבוי / חסום במדיניות) |
| האייקון לא עולה בהתחברות | הקובץ הוזז אחרי רישום המשימה — רשום מחדש |
| לחיצה כפולה לא עושה כלום | בקשת ה-UAC בוטלה |

הכלי כותב יומן דק לצד הסקריפט, בקובץ `defender-tray.log` — שם אפשר לראות מתי הוא עלה,
מה נשלח ומה נכשל. אם התיקייה אינה ניתנת לכתיבה, הכלי ממשיך לעבוד בלי יומן.
